# AlephMapper 0.8.1 — release notes (proposed)

## Features

- C# 14 instance extension methods now support `[Updatable]` for source-generated
  update-in-place companions. The extension receiver is the source parameter and
  `dest` is the final argument of the generated static overload.
- C# 14 instance extension methods now support `[Adapt]` with explicit alternate
  source/destination types, including `AdaptGeneration.Map`,
  `AdaptGeneration.Expression` and `AdaptGeneration.Update`.
- The existing C# 14 `[Projectable]` expression factories remain supported.
  Getter-only extension properties remain projection-only.

## Compatibility and limitations

- Classic mappings continue to work on Roslyn 4.8+; C# 14 extension members
  require a Roslyn 5.0+ compiler and C# 14 language mode.
- Adaptation retains the existing explicit type/member/constructor validation.
- Update-in-place still requires a reference-type destination with a supported
  object construction/initializer shape. Value-type results report `AM0001`.
- Generic extension blocks, block-bodied methods, static members, unsupported
  receiver/argument forms and cross-assembly source expansion remain outside scope.
- Neither `[Updatable]` nor `[Adapt]` is enabled implicitly on extension
  methods by an attribute on the containing class.

## Tests and documentation

- Added generator compile/runtime tests for projection, update and adaptation
  from one C# 14 instance method, including `dest` preservation.
- Added runtime and EF Core SQLite projection coverage.
- Extended the packaged Roslyn 5+ compatibility consumer to exercise the
  new generated APIs.
- Updated README, compatibility matrix and agent guidance for 0.8.1.

**Release status:** documentation for the proposed pull request only. This
