# Generated API reference

This page describes the API generated by the current `0.8.3` source tree. The complete, runnable source for every marked snippet is [the documentation fixture](../examples/Documentation/Program.cs). Run it with `dotnet run --project examples/Documentation/Documentation.csproj --configuration Release` from the repository root. The fixture uses the source project as an analyzer, so this is a source-version example; check [installation](installation-and-compatibility.md) for package use.

## Declaration and attribute rules

Classic mappings are `static`, expression-bodied methods in a `static partial` class. `[Projectable]` and `[Updatable]` may mark the class or a method. A method attribute enables its companion even if the class is unmarked. For `NullConditionalRewrite` and `CollectionProperties`, a method setting takes precedence over a class setting; otherwise the class setting or the default applies. `[Adapt]` is method-only and repeatable for distinct explicit type pairs. These attributes are embedded into the consuming compilation by the analyzer. A `[Projectable]` property target is supported only for the C# 14 extension-property form described below; extension update generation requires a member-level `[Updatable]` on a supported method.

| Attribute | Targets | Default |
| --- | --- | --- |
| `[Projectable]` | Class, method, property | `NullConditionalRewrite.Ignore` |
| `[Updatable]` | Class, method | `CollectionPropertiesPolicy.Skip` |
| `[Adapt]` | Method | `Map | Expression`, `NullConditionalRewrite.Ignore`; `Name` is required for expression generation |

Generated companions are public static members of the containing mapper class. The handwritten method keeps its own declared accessibility and ordinary C# behavior. The generated members carry method type parameters and constraints where supported; `[Adapt]` on a generic mapping method reports [AM0018](diagnostics.md#am0018).

## Projection factory

<!-- docs-example:projection -->
```csharp
[Projectable]
public static PersonDto ToDto(Person person, int year) => new()
{
    Id = person.Id,
    Name = FullName(person),
    Age = year - person.BirthYear
};

private static string FullName(Person person) =>
    person.FirstName + " " + person.LastName;
```
<!-- /docs-example -->

The generated signature for this mapping is:

```csharp
public static Expression<Func<Person, PersonDto>> ToDtoExpression(int year);
```

The first mapping parameter becomes the lambda parameter; later parameters become factory arguments. The `FullName` helper is inlined into the tree. The handwritten call `ToDto(person, 2026)` executes ordinary C#. Calling `ToDtoExpression(2026)` constructs a tree; `Compile()` executes that tree in memory. Passing the tree to a LINQ provider asks that provider to translate its nodes. Successful C# generation does not prove SQL translation. See the [SQLite integration tests](../tests/AlephMapper.IntegrationTests) for tested provider cases.

The generator does not add a universal null-source guard to ordinary mappings or projection factories. If a body dereferences its source, a null source follows that body's C# or expression semantics. For `?.`, the default `Ignore` policy removes the conditional in generated expressions; choose `Rewrite` when the null check must be retained and its receiver is stable.

## Update overload

<!-- docs-example:update -->
```csharp
[Updatable]
public static PersonDto UpdateTemplate(Person person) => new()
{
    Id = person.Id,
    Name = person.FirstName + " " + person.LastName
};
```
<!-- /docs-example -->

The generated signature is `public static PersonDto UpdateTemplate(Person person, PersonDto dest)`. It returns the destination reference. A null source returns `dest` without assignments. A null destination is created before assignments. Update generation for non-nullable value-type destinations is skipped with [AM0001](diagnostics.md#am0001). Collections are skipped by default; `CollectionPropertiesPolicy.Update` opts into assignment of mapped collection values. Replacing a tracked collection can affect relationships, so verify that behavior in the consuming EF Core model. See [advanced usage](advanced-usage.md#updating-existing-objects).

## Explicit adaptation

<!-- docs-example:adaptation -->
```csharp
[Adapt(typeof(Employee), typeof(EmployeeDto), Name = "ToEmployeeDto")]
public static PersonDto AdaptTemplate(Person person) => new()
{
    Id = person.Id,
    Name = person.FirstName + " " + person.LastName
};
```
<!-- /docs-example -->

This generates `ToEmployeeDto(Employee person)` and `ToEmployeeDtoExpression()` returning `Expression<Func<Employee, EmployeeDto>>`. The generated name is provided by `Name`; by default `Generate` requests map and expression. Include `AdaptGeneration.Update` to request a third overload with `EmployeeDto dest`. Adaptation substitutes only the declared source/destination pair, validates used paths and writable destination members, and checks the generated result with Roslyn. It does not discover pairs by convention. See the full [adaptation guide](Adapt-Attribute.md).

An adapted map and expression retain the template body's null-source behavior; only an update overload adds the null-source/null-destination handling described above.

## C# 14 extension member

<!-- docs-example:extension -->
```csharp
extension(Person person)
{
    [Projectable]
    public string DisplayName => person.FirstName + " " + person.LastName;
}
```
<!-- /docs-example -->

The getter-only property generates `PersonExtensions.DisplayNameExpression()` returning `Expression<Func<Person, string>>`. Extension properties are projection-only. Supported instance extension methods may also request update and adaptation companions; the generated methods are static members of the outer partial class. C# 14 requires the Roslyn 5.0 analyzer band and a C# 14 host. See the [extension compatibility matrix](extension-members-compatibility-matrix.md) for supported and rejected forms.

## Compiling call sites

<!-- docs-example:calls -->
```csharp
var direct = PersonMapper.ToDto(person, 2026);
var projected = people.Select(PersonMapper.ToDtoExpression(2026)).Single();
var adults = people.Where(PersonMapper.IsAdultExpression(2026)).ToList();
var destination = new PersonDto();
PersonMapper.UpdateTemplate(person, dest: destination);
var employee = new Employee { Id = 2, FirstName = "Grace", LastName = "Hopper", BirthYear = 1906 };
var adapted = PersonMapper.ToEmployeeDto(employee);
var adaptedExpression = PersonMapper.ToEmployeeDtoExpression().Compile()(employee);
var name = people.Select(PersonExtensions.DisplayNameExpression()).Single();
```
<!-- /docs-example -->

Projection and adaptation can fail independently: a handwritten method can remain callable when a generated companion is omitted. Inspect [diagnostics](diagnostics.md) and the emitted file when a companion is absent. Suppressing a warning does not emit that member. Null-conditional rewriting, switch lowering, and helper expansion can change evaluation count or null behavior; review [advanced usage](advanced-usage.md) and the [switch matrix](switch-parity-matrix.md).
