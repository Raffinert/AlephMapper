# AlephMapper 0.9.0 — release notes

This release makes `[Updatable]` update overloads produce the same values as the mapping they are generated from. It is a minor-version bump because some shapes now get no update overload, or a different one, than 0.8.3 generated.

## Update-in-place semantics

- Nested objects are created when missing and then updated member by member. This now also works for inherited members, for several members of the same type, and under `CollectionPropertiesPolicy.Update`. Previously each of these could throw `NullReferenceException`.
- Members are resolved from the destination type symbols. The lookup covers base types, interfaces, type-parameter constraints and fields, and finds the inherited setter of a property whose override redeclares only the getter.
- Struct and `Nullable<T>` members are assigned as a whole. Previously a struct object initializer was replaced by a comment and its values were lost. Members typed by a type parameter without a `class` constraint are also assigned as a whole.
- Some nested objects cannot be updated in place: those created with constructor arguments, with `init`-only members, without an object initializer, or as a type other than the member's declared type. These are replaced with the mapped instance, so their values and runtime type match the mapping.
- Types with `required` members, or without an accessible parameterless constructor, are created with the mapping's own expression when missing.
- `Member = { ... }` without `new` updates the instance the destination already holds.
- A conditional member is split into `if`/`else` only when a branch is updated in place. Otherwise the whole conditional is assigned, which keeps its natural type: `c ? 5 : default` assigns `0` to an `int?`.
- Interpolated strings keep their format and alignment clauses, escapes, and verbatim or raw form.
- A root `cond ? new T { ... } : null` becomes a guard, also when the null branch is written as `null!`, `default` or a cast. When the mapping yields no value, the existing destination is returned unchanged. Previously the condition could be ignored, or the destination was replaced by `null`.
- A root `source == null ? throw ... : new T { ... }` keeps throwing for a `null` source.
- A root that creates a derived type creates that type when the destination is `null`.
- Escaped member names such as `@event` are emitted correctly.

## Diagnostics

- **New `AM0023` (warning).** It is reported when the root creation cannot be applied to an existing destination. The causes are constructor arguments, an `init`-only member, a member that exists only on a derived type, or a nested collection initializer under `CollectionPropertiesPolicy.Update`. No update overload is generated, where 0.8.3 emitted code that did not compile or silently dropped values.
- **`AM0001` now also covers `Nullable<T>` returns** such as `Point?`, which previously produced code that did not compile.

## Compatibility notes

- A root `new Target(id) { ... }` on a type that also has a parameterless constructor used to compile while ignoring `id`. It now reports `AM0023` and loses its update overload.
- Callers of an update overload that is no longer generated get a compile error. The cases are the root shapes listed for `AM0023` and `Nullable<T>` returns.
- Generated code for the shapes listed above changes. Existing simple mappings generate the same code as in 0.8.3.
